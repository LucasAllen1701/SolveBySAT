# Solve By SAT: milestone 8 plan (scale, with a rewriting probe first)

Lucas Allen · 24 November 2026

**Status: 8a (the rewriting probe) is complete (sections 2, 4.1 and 4.2). 8b has started: Claude Code measures the structure of the CNF (4.3), then the scale design note is written in the claude.ai project. The encoding stays one-shot (4.2).** EVAL_PLAN section 10.11 records why milestone 8 is scale and why the probe comes first.

## 1. Aims

Milestone 8 shrinks groundness and decomposition, the two clause families behind nearly every memory crash in milestone 7 (SPEC 7.4). It starts with a probe of rewriting, because rewriting is the extension the evaluation points to (SPEC 9.5), and because it adds clauses mostly to groundness. The probe tells the scale work what rewriting will need.

| Stage | Work |
| --- | --- |
| 8a | Rewriting probe: rewriting by first-order equality rules, given to the unchanged tactic as generated lemmas (section 2) |
| 8b | Scale design note, written in the claude.ai project with the 8a results in hand |
| 8c and later | Implementing and evaluating the scale design, planned after 8b |

The milestone 7 rules carry over: filters, seeds, samples and limits are pre-registered and not changed after seeing results. A decoder failure on a satisfiable CNF is a bug. Every result records its code version.

## 2. The rewriting probe (8a)

### 2.1 Question

How many of the goals whose milestone 7 obstacles are all rewriting constants does the unchanged tactic prove, at N ≤ 10, once it is given rewriting by first-order equality rules? At what N and CNF size does it prove them? And what do the rules cost on goals it already proves?

The probe changes nothing in `SolveBySat/`. The rules are ordinary lemmas, generated by the harness and passed in H.

### 2.2 Goals

- **Rewriting goals.** The population is the main-run goals that the compiler accepts, that are not proved in milestone 7's final results, and whose E5 obstacles all fall in family 3A (EVAL.md E5: 522 in Tier A, 946 in Tier B). Take 100 Tier B and 50 Tier A goals. Rank each tier's keys by a hash of seed 80101 and the key (EVAL_PLAN 10.8 decision 4), and take the first ones.
- **Control goals.** The 50 scaling goals of milestone 7 (`eval/scaling_goals.jsonl`), all proved, at their original N.

### 2.3 The rules

For each goal, collect the symbols that occur in its preprocessed statement and in the statements of its accepted H_main constants. For each symbol and each eligible argument position, generate:

- **congruence**, for a function symbol `f` and position i: `a = b → f x₁ … a … xₙ = f x₁ … b … xₙ`, proved by `congrArg (fun y => f x₁ … y … xₙ)`;
- **substitution**, for a predicate symbol `P` (the head of an atom, `Eq` included) and position i: `a = b → P x₁ … b … xₙ → P x₁ … a … xₙ`, proved by `▸`, or `Eq.mpr` with that motive;
- **at a position of type `Prop`**, the same two rules with `A ↔ B` in place of `a = b`, proved through `propext`.

Rules on the details:

- **Eligible positions** are explicit arguments whose values are terms: not types, instances or proofs, and not an argument on which another argument's type depends.
- **Each rule is universally quantified** over the symbol's other arguments and universe parameters, and is built with `addDecl` in the harness (`_probe.<symbol>.<kind>.<i>`), so the kernel checks every rule.
- **H** is the accepted H_main constants, then `Eq.refl`, `Eq.symm` and `Eq.trans` if they are not already there, then the rules in name order.
- **Bookkeeping.** Record each goal's number of rules. Record any rule that fails to build, or that the compiler rejects, with its reason; such a rule is left out, and this is not a stop.

The rules do not include `of_eq_true`, `eq_true`, `eq_false` or `congrFun'`. These are `simp`'s own steps; a user's rewriting proof does not need them. Goals whose only route goes through them will show as no proof.

### 2.4 Runs and limits

- **Settings.** One run per goal, with the N loop from 1 to 10 and milestone 7's limits: solver 20 s per call, N loop 120 s, watchdog 300 s, 2.5 GB cgroup cap, P = 1, all refinements on.
- **Record** the outcome, the N found, the per-N record of the full run, whether the proof uses a generated rule, the number of rules, and the time.
- **Sizes.** For every run, also record the `countOnly` counts per family at N = 5 and at the run's last N, in their own capped processes, so crashed runs have sizes too.
- **Control goals** run their N loop up to their original N, as in milestone 7's section 4.2.

### 2.5 Stop rules

- A decoder failure on a satisfiable CNF stops the run, as always.
- A control goal that ends within every limit without a proof at or below its original N stops the run. Adding lemmas cannot remove a proof.
- A rewriting goal whose proof uses only its H_main constants stops the run until it is explained. Milestone 7 found no such proof with the same H_main and limits.

### 2.6 Pilot, projection and full run

- **Pilot.** Run the 10 highest-ranked Tier B goals, the 5 highest-ranked Tier A goals and the 5 highest-ranked control goals. Then stop with a projection for the 200 runs, broken down by group.
- **Full run.** It needs the owner's approval. If the projection exceeds about 24 hours, propose fewer goals per group and wait.

### 2.7 Report

`eval/m8a/report.py` writes `eval/m8a/PROBE.md` from the data files alone. It covers:

- outcomes per group;
- proved at N;
- the proved share by number of rules;
- CNF sizes and family shares, against milestone 7's for the same goals;
- for the control goals, the cost of the rules: clauses at the original N, against milestone 7, and whether they stay feasible.

The report states facts. Reading them is for 8b.

### 2.8 Data

- **Branch.** The probe runs on a branch `m8` made from `main` after the milestone 7 merge.
- **Inputs.** These are the records of the 200 goals, extracted from tag `m7-data` (corpus records, compiler verdicts, final results, the E5 table and facts, the scaling goals) into `eval/m8a/inputs/`, with md5 sums, before any run.
- **Outputs.** These go under `eval/m8a/`.
- **At the end of milestone 8**, the code and reports go to `main` and the bulk data stays on the branch as an archive, as for milestone 7.

## 4. Amendments

### 4.1 Before the full 8a run (24 November 2026)

**Pilot record.** NOTES.md ("8a: probe set-up and pilot") has the details.

- **Runs.** 20 runs, and no stop rule fired.
  - Rewriting goals: 1 of 15 proved (Tier B, N = 2, with a congruence rule). The other 14 hit the 2.5 GB cap at N = 3 to 10, with groundness plus decomposition at 95–99% of the clauses.
  - Controls: 4 of 5 proved at their original N. One became infeasible with the rules (memory).
- **Cost of the rules.** Where milestone 7 has a CNF at the same N, the rules multiply a rewriting goal's CNF by 2.3 to 17. They multiply a control's CNF at its original N by 1.9 to 39.
- **Projection** for the 200 runs: 3.3 hours.

**Finding: no `↔` rule is usable.**

- The unchanged compiler rejects all 162 `subst_iff` rules, and no `congr_iff` rule was built. Their premise `a ↔ b` over Prop variables compiles to clauses whose head is a clause variable. So the rules as written give nothing at a Prop position.
- This is a defect of the rule set, found during the set-up. It is not a result: no pilot outcome depends on it, because the pilot's failures are memory crashes.
- It matters. 38 of the 150 sampled rewriting goals (428 of the 1,468 in the population) have `propext` among their obstacles, and 9 (86) have only `propext`. Many of these are equations between propositions, closed by `propext` applied to an `↔` lemma that is already in H_main. For example, `(¬p ≤ s.startPos) = (s.startPos < p)` follows from `Std.not_le`.

**Decisions.**

1. **Rules at Prop positions use `=`.** At a position of type `Prop`, the congruence and substitution rules take `a = b`, like every other position, in place of `a ↔ b`. The `↔` rules are no longer generated.
2. **`propext` equations.** Take each accepted H_main constant, and each split path of its statement (SPEC 4.2) whose head is `L ↔ R`. For each, generate `_probe.<constant>.propext.«<path>»`, with the same binders and premises and the head `L = R`, proved through `propext`. This is what `rw` does with an `↔` lemma. It turns every `↔` lemma into an equation that the congruence and substitution rules can use, without a Prop variable as a head.
3. **Eligibility.** A position on which the symbol's result type depends is not eligible. Such rules cannot build (for example `OfNat Nat y` and `Decidable (y < m)`), so they are no longer attempted. Record how many positions are skipped for this reason.
4. **The full run repeats the 20 pilot specs** with the amended rules, so all 200 runs use one rule set. The pilot's results stay as a record in `eval/m8a/pilot/` and are not merged into the full run's.
5. **Hand examples.** Add these to `Test/M8Probe.lean`, each with its minimality check. The first two replace P3 and P4.
   - `(¬ a ≤ b) = (b < a)` for `a b : Nat`, from `Nat.not_le`, at 1 node.
   - `Q (¬ a ≤ b) → Q (b < a)` for `Q : Prop → Prop`, from `Nat.not_le`, through a substitution rule at a Prop position.
   - `A ∧ B` from `hA : A`, `h : B ↔ C` and `hC : C`, with no rules at all. Rewriting with `↔` under a logical connective in the goal is already in the tactic's class, through `And.intro` and `Iff.mpr`.
6. **Report additions (2.7).** Report the goals with `propext` among their obstacles separately. For each proof, record whether it uses a `propext` equation.
7. **Set-up decisions accepted** (NOTES.md):
   - the controls are ranked by the same hash rule and seed;
   - rule indices are string name components;
   - there is no k = 0 stop rule for the controls, and the monotonicity rule is kept;
   - the controls are also sized at their original N.

**A limit of the probe.** A local hypothesis `h : L ↔ R` (a binder of the goal) gets no `propext` equation, because the probe can only add global lemmas. The tactic-level design for milestone 9 covers local hypotheses too.

### 4.2 After the full 8a run (24 November 2026)

**8a record.** NOTES.md ("8a: the full run") and `eval/m8a/PROBE.md` have the details. The run was checked independently: the 200 results recount, no stop rule fired, every rewriting proof uses a constant outside H_main, and PROBE.md regenerates byte-identically.

| group | runs | proved | memory crash | solver timeout | no proof ≤ N |
| --- | --- | --- | --- | --- | --- |
| rewriting, Tier B | 100 | 16 | 52 | 31 | 1 |
| rewriting, Tier A | 50 | 5 | 33 | 10 | 2 |
| control | 50 | 43 | 6 | 1 | 0 |

- **Rewriting works where the CNF fits.** 21 goals that milestone 7 did not prove are proved, at N = 1 to 8. `propext` equations prove 8 of the 28 Tier B goals with a `propext` obstacle.
- **The rules are expensive.** They multiply the CNF at N = 5 by a median of 13–18 (5 for the controls), with groundness plus decomposition at 95–96%. No rewriting goal with more than 10 accepted rules is proved.
- **Limits replace answers.** 87 of the 110 rewriting goals with a certified "no proof ≤ 10" in milestone 7 now end at a resource limit. 42 of all runs end at the 20 s solver limit, so solving time is a limit as well as memory.

**Decision: the encoding stays one-shot.**

- The owner keeps SPEC 1's one-shot property for milestone 8. The CNF is built once, before the solver runs, and nothing is fed back from Lean or from the solver.
- So the scale design (8b) makes the single CNF smaller. It does not add clauses lazily.
- A possibly very large CNF is an acceptable output. The user decides whether to solve it, and with which solver.

**Deferred: a lazy option.** An incremental mode would solve with most decomposition and groundness clauses left out, check the model, add the clauses it violates, and repeat, as SMT solvers do for congruence. It is to be revisited when the project is complete, as an option for the user alongside the one-shot mode, not in its place. It is not part of milestone 8.

### 4.3 8b starts with measurements (24 November 2026)

The scale design (8b) is written in the claude.ai project. It needs numbers that neither milestone 7 nor 8a recorded: where the groundness and decomposition clauses come from, and which of them a proof can ever use. Claude Code measures these first, without changing the CNF the tactic builds.

**Points.**

- **Structure (M1 to M4).** The 200 goals of 8a at N = 5, each twice: with the 8a rules (amendment 4.1), and with milestone 7's H, without rules. That makes 400 points.
- **Models (M5).** The 64 proved runs of 8a (21 rewriting goals and 43 controls), at the N where each was proved.

**Measurements.**

- **M1, label width.** The bits of each label field (`sym`, `idx`, `rank`, `esc`, `open`; SPEC 5.3), and W.
- **M2, groundness by candidate.** Clauses and `sv` variables (SPEC 6.8), split:
  - by the candidate's kind: ground object, eigenvariable slot, rigid position or value object;
  - by the candidate's node index against the slot's: the same node, a smaller index, or a larger one.
  Also count the candidates that the static typing decision drops.
- **M3, decomposition by pair.** Clauses (SPEC 6.5), split:
  - by whether the two objects belong to the same node or to different nodes;
  - per symbol, for the 10 symbols with the most clauses;
  - by whether the two objects' templates lie in the same static may-equal component. Claude Code defines that component and records the rule. A natural rule joins template positions linked by matching, by links and by groundness candidates, with all node copies of a template identified.
- **M4, node–clause bounds.**
  - For each goal or data position g, compute its least depth d(g) in the forest, and its least proof size s(g), by a fixpoint that ignores unification.
  - In any proof tree whose parents precede their children, a node at index α has depth at most α. Its subtree has at least as many nodes as the size of its own proof, all of them with indices of α or more.
  - So `gp(α, g)` is possible only if d(g) ≤ α and α + s(g) ≤ N. A pair (α, c) is possible only if some goal position g that c can match passes this test, with c's own minimal size (1 plus its premises' least sizes) in place of s(g).
  - Report the share of `gp` and `cl` pairs that the bounds exclude, and the share of groundness and decomposition clauses that depend only on excluded pairs.
  - Claude Code checks the argument against the encoding before counting, and records any flaw.
- **M5, models.** For each proved run, read from the model:
  - for every grounded slot, the kind of the chosen candidate, and its node's relation to the slot's node in the decoded tree (the same node, an ancestor, a descendant, or neither);
  - the `gp` and `cl` pairs used. Every one must pass the M4 bounds. A violation means the bounds are wrong, and it stops the work.

**Rules.**

- The CNF the tactic builds does not change. Diagnostic code is new code, or hooks that are off by default. The 36 named cases and the SPEC 7.3 instances must give byte-identical DIMACS with and without it.
- The measurements are facts for the design. Reading them is for the design note.
- **Report.** `eval/m8b/report.py` writes `eval/m8b/DIAG.md` from the data files alone. It must regenerate byte-identically.
