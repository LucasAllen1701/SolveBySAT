# Solve By SAT: milestone 8 plan (scale, with a rewriting probe first)

Lucas Allen · 24 November 2026

**Status: 8a (the rewriting probe) is pre-registered, and nothing has run yet. The scale design (8b) is still to be written.** EVAL_PLAN section 10.11 records why milestone 8 is scale and why the probe comes first.

## 1. Aims

Milestone 8 shrinks groundness and decomposition, the two clause families behind nearly every memory crash in milestone 7 (SPEC 7.4). It starts with a probe of rewriting, because rewriting is the extension the evaluation points to (SPEC 9.5), and because it adds clauses mostly to groundness. The probe tells the scale work what rewriting will need.

| Stage | Work |
| --- | --- |
| 8a | Rewriting probe: rewriting by first-order equality rules, given to the unchanged tactic as generated lemmas (section 2) |
| 8b | Scale design note, written in the claude.ai project with the 8a results in hand |
| 8c and later | Implementing and evaluating the scale design, planned after 8b |

The milestone 7 rules carry over: filters, seeds, samples and limits are pre-registered and not changed after seeing results. A decoder failure on a satisfiable CNF is a bug. Every result records its code version.

## 2. The rewriting probe (8a)

### 2.1 Question

How many of the goals whose milestone 7 obstacles are all rewriting constants does the unchanged tactic prove, at N ≤ 10, once it is given rewriting by first-order equality rules? At what N and CNF size does it prove them? And what do the rules cost on goals it already proves?

The probe changes nothing in `SolveBySat/`. The rules are ordinary lemmas, generated by the harness and passed in H.

### 2.2 Goals

- **Rewriting goals.** The population is the main-run goals that the compiler accepts, that are not proved in milestone 7's final results, and whose E5 obstacles all fall in family 3A (EVAL.md E5: 522 in Tier A, 946 in Tier B). Take 100 Tier B and 50 Tier A goals. Rank each tier's keys by a hash of seed 80101 and the key (EVAL_PLAN 10.8 decision 4), and take the first ones.
- **Control goals.** The 50 scaling goals of milestone 7 (`eval/scaling_goals.jsonl`), all proved, at their original N.

### 2.3 The rules

For each goal, collect the symbols that occur in its preprocessed statement and in the statements of its accepted H_main constants. For each symbol and each eligible argument position, generate:

- **congruence**, for a function symbol `f` and position i: `a = b → f x₁ … a … xₙ = f x₁ … b … xₙ`, proved by `congrArg (fun y => f x₁ … y … xₙ)`;
- **substitution**, for a predicate symbol `P` (the head of an atom, `Eq` included) and position i: `a = b → P x₁ … b … xₙ → P x₁ … a … xₙ`, proved by `▸`, or `Eq.mpr` with that motive;
- **at a position of type `Prop`**, the same two rules with `A ↔ B` in place of `a = b`, proved through `propext`.

Rules on the details:

- **Eligible positions** are explicit arguments whose values are terms: not types, instances or proofs, and not an argument on which another argument's type depends.
- **Each rule is universally quantified** over the symbol's other arguments and universe parameters, and is built with `addDecl` in the harness (`_probe.<symbol>.<kind>.<i>`), so the kernel checks every rule.
- **H** is the accepted H_main constants, then `Eq.refl`, `Eq.symm` and `Eq.trans` if they are not already there, then the rules in name order.
- **Bookkeeping.** Record each goal's number of rules. Record any rule that fails to build, or that the compiler rejects, with its reason; such a rule is left out, and this is not a stop.

The rules do not include `of_eq_true`, `eq_true`, `eq_false` or `congrFun'`. These are `simp`'s own steps; a user's rewriting proof does not need them. Goals whose only route goes through them will show as no proof.

### 2.4 Runs and limits

- **Settings.** One run per goal, with the N loop from 1 to 10 and milestone 7's limits: solver 20 s per call, N loop 120 s, watchdog 300 s, 2.5 GB cgroup cap, P = 1, all refinements on.
- **Record** the outcome, the N found, the per-N record of the full run, whether the proof uses a generated rule, the number of rules, and the time.
- **Sizes.** For every run, also record the `countOnly` counts per family at N = 5 and at the run's last N, in their own capped processes, so crashed runs have sizes too.
- **Control goals** run their N loop up to their original N, as in milestone 7's section 4.2.

### 2.5 Stop rules

- A decoder failure on a satisfiable CNF stops the run, as always.
- A control goal that ends within every limit without a proof at or below its original N stops the run. Adding lemmas cannot remove a proof.
- A rewriting goal whose proof uses only its H_main constants stops the run until it is explained. Milestone 7 found no such proof with the same H_main and limits.

### 2.6 Pilot, projection and full run

- **Pilot.** Run the 10 highest-ranked Tier B goals, the 5 highest-ranked Tier A goals and the 5 highest-ranked control goals. Then stop with a projection for the 200 runs, broken down by group.
- **Full run.** It needs the owner's approval. If the projection exceeds about 24 hours, propose fewer goals per group and wait.

### 2.7 Report

`eval/m8a/report.py` writes `eval/m8a/PROBE.md` from the data files alone. It covers:

- outcomes per group;
- proved at N;
- the proved share by number of rules;
- CNF sizes and family shares, against milestone 7's for the same goals;
- for the control goals, the cost of the rules: clauses at the original N, against milestone 7, and whether they stay feasible.

The report states facts. Reading them is for 8b.

### 2.8 Data

- **Branch.** The probe runs on a branch `m8` made from `main` after the milestone 7 merge.
- **Inputs.** These are the records of the 200 goals, extracted from tag `m7-data` (corpus records, compiler verdicts, final results, the E5 table and facts, the scaling goals) into `eval/m8a/inputs/`, with md5 sums, before any run.
- **Outputs.** These go under `eval/m8a/`.
- **At the end of milestone 8**, the code and reports go to `main` and the bulk data stays on the branch as an archive, as for milestone 7.
