**Caveat (§10.8 decision 3).** 438 of the 1,028 changed goals crashed on memory both before and after the fix, so the fix's effect on them is not measured: a goal that crashed both times may or may not have a proof within N ≤ 10 that the bug excluded. The fix can also change a CNF's size, so a result can move towards a resource limit: 3 changed goals went from no proof ≤ 10 to a resource limit: `main:A/Std.DTreeMap.Equiv.inter_congr` (solver timeout); `main:B/StateT.run_map/1` (memory crash, last N 10); `main:B/StateT.run_map/2` (memory crash, last N 10).

**Spot check (§10.7 decision 5).** 100 goals whose forest did not change were also rerun; their original line stands. Original outcome → rerun outcome: no proof ≤ 10 → no proof ≤ 10 59; memory crash → memory crash 23; proved → proved 13; memory crash → no proof ≤ 10 2; solver timeout → solver timeout 2; memory crash → solver timeout 1. Proved goals keep their N in 13 of 13. Every difference has a resource limit on one of the runs, which the check allows (`eval/final/merge_report.txt`).
